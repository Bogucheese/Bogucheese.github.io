AI Agent 原理与技术教程（一）：核心定义、系统组成与运行机制

2026-09-21 技术教程 / AI AI Agent · LLM · 智能体 · 教程

这是《AI Agent 原理与技术》系列教程的第一篇，从最核心的概念讲起：
Agent 到底是什么、由哪些模块组成、如何运转、有哪些类型、适合什么场景。
全文以「旅行预订 Agent」为贯穿示例，帮助建立对 Agent 系统的整体认知框架。

一、AI Agent 核心定义

1. 广义定义（经典人工智能范畴）

AI Agent（智能体）是一类能够感知外部环境、自主做出决策、并通过动作作用于环境的智能系统。该概念远早于大语言模型（LLM）诞生，早期的 Agent 多基于硬编码规则、专家系统实现，能力边界由开发者预先设定。

2. 狭义定义（LLM 时代主流）

我们当下常说的 AI Agent，特指以大语言模型为核心决策大脑的智能系统：它通过 LLM 理解自然语言指令、推理上下文逻辑、制定行动规划，再通过调用工具与外部环境交互，最终完成复杂任务，实现从「文字生成」到「实际做事」的能力跃迁。

二、AI Agent 核心组成

AI Agent 是一个多模块协同的系统，经典架构包含四大核心组件，LLM 时代的 Agent 在此基础上扩展了记忆与知识模块。

1. 四大核心基础组件

组件 定位 功能说明 旅行预订 Agent 示例
交互环境 Agent 所处的外部场域与交互边界 Agent 所有感知和行动的载体，决定了 Agent 的能力边界范围 机票酒店预订平台、用户对话界面
感知单元（传感器） Agent 的「信息输入接口」 感知环境的当前状态与变化，将外部信息转化为决策核心可处理的格式 查询酒店房态、读取航班价格、获取用户历史订单
决策核心 Agent 的「大脑」 接收感知信息，基于规则/模型推理判断，生成行动指令 早期为硬编码规则；LLM Agent 中为大语言模型，负责理解需求、规划行程、判断操作逻辑
执行单元（执行器） Agent 的「动作输出接口」 接收决策核心的指令，对环境产生实际作用 提交酒店订单、发送确认短信、取消预订操作

2. 扩展核心：记忆与知识体系

这是 LLM Agent 区别于传统规则 Agent 的关键模块，分为两类：

  • 短期记忆（上下文记忆）：存储当前对话/任务的交互过程与中间状态，支撑多轮连续推理，例如当前用户的出行目的地、已选航班信息。
  • 长期记忆（知识库）：持久化存储历史交互数据、领域知识与用户偏好，支撑个性化与持续优化，例如用户常住的酒店品牌、历史出行习惯。

三、LLM Agent 核心运行机制

LLM Agent 以「感知-决策-执行-反馈」的闭环模式运行，完整流程如下：

  1. 感知阶段：感知单元通过工具调用，获取环境状态与用户需求，传递给决策核心。

  2. 决策阶段：LLM 基于输入信息、上下文记忆和知识库进行推理，拆解任务步骤，生成具体的工具调用指令。

    注：LLM 本身不直接执行操作，仅负责生成决策与指令，是「思考者」而非「执行者」。

  3. 执行阶段：执行单元接收指令，通过调用对应工具完成实际操作，作用于外部环境。

  4. 反馈阶段：执行结果回传给感知单元，再次输入 LLM 进行校验，判断任务是否完成，若未完成则进入下一轮闭环。

其中，工具是感知单元与执行单元的具体实现载体：查询类工具对应感知能力，操作类工具对应执行能力；工具的可用范围由交互环境与开发者授权共同决定。

四、AI Agent 常见类型

AI Agent 可从决策智能层级和系统架构模式两个独立维度分类，不同维度的类型可叠加存在。

维度一：按决策智能层级（单 Agent 决策模式）

该分类按照 Agent 的决策逻辑复杂度与智能水平划分，是单 Agent 的核心分类方式。

类型 核心特征 示例
简单反射 Agent 完全基于硬编码规则响应，无记忆、无规划，仅对特定感知输入做出固定动作 收到投诉邮件后自动转发给客服部门，不做额外处理
基于模型的反射 Agent 维护内部环境状态模型，能跟踪环境变化并基于状态做出响应，具备基础状态记忆 跟踪历史航班价格波动，标记出价格突然上涨的航线并触发预警
目标驱动 Agent 具备明确目标，能够自主拆解任务、规划行动路径，逐步推进目标达成 根据用户的出发地与目的地，自主规划并预订包含航班、接送机、酒店的完整行程
效用驱动 Agent 不止满足于达成目标，还会基于效用函数（成本、效率、偏好等维度）权衡方案，输出最优解 在满足出行时间的前提下，平衡价格与中转时长，选出最符合用户偏好的行程方案
学习型 Agent 能通过任务反馈自动优化决策逻辑，随着交互积累持续提升效果 根据用户行程结束后的满意度评分，调整后续酒店、航班的推荐策略

维度二：按系统架构与协作模式（系统结构维度）

该分类按照 Agent 的系统组成与协作方式划分，聚焦多模块/多主体的组织形式。

类型 架构特点 示例
分层 Agent 由一个主 Agent 统筹全局，将复杂任务拆分为子任务，委派给下层子 Agent 分别执行，最终汇总结果 收到「取消全部行程」请求后，主 Agent 拆分任务，分别调度子 Agent 执行取消航班、取消酒店、取消租车的操作
多 Agent 系统 由多个独立且具备完整能力的 Agent 组成，通过协作或竞争共同完成全局目标 协作模式下，酒店 Agent、航班 Agent、娱乐 Agent 分别负责对应板块，共同生成完整旅行方案；竞争模式下，多个采购 Agent 同时竞价酒店房源，争取最低预订价格

五、AI Agent 适用场景

AI Agent 并非适用于所有场景，当任务满足以下特征时，使用 Agent 架构收益最高：

  • 开放式复杂问题：解决路径不固定，需要动态探索、灵活调整，无法通过预编程的固定步骤完成，例如开放式行业调研、复杂问题排查。
  • 多步骤流程任务：任务需要多轮调用不同工具、跨系统交互，而非单次查询或单步生成，例如完整业务办理、全链路自动化运维。
  • 需持续优化的场景：系统需要基于用户反馈、环境变化持续迭代能力，而非一成不变的固定逻辑，例如个性化推荐系统、自适应运营助手。
