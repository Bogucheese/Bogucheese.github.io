一、引言

1. OpenTenBase 是什么

OpenTenBase 是腾讯开源的企业级分布式数据库管理系统，由 OpenAtom 开放原子基金会孵化，前身是 TDSQL 社区版与 Postgres-XL 项目。它采用无共享（share-nothing）架构，集群由三类节点组成：

  • GTM（全局事务管理器）：负责分布式事务号与全局一致性；
  • CN（协调节点 Coordinator）：只存元数据，接收 SQL 后拆分下发；
  • DN（数据节点 DataNode）：存储分片数据。

用户统一连接 CN，对上层应用透明。内核基于 PostgreSQL 10，兼容大部分 PG 语法与生态工具。

本教程记录了在 Ubuntu 22.04 上从零开始源码编译、部署并验收一套单机分布式集群（1 个 GTM + 1 个 CN + 2 个 DN）的完整过程，重点是解决官方文档没有覆盖到的依赖与兼容性问题。全部命令均在下述实测环境中验证通过。

3. 为什么需要这篇教程

官方 README 列出的支持系统是 TencentOS 2/3、OpenCloudOS 8.x、CentOS 7/8 和 Ubuntu 18.04，Ubuntu 22.04 并不在列。直接照官方步骤在 Ubuntu 22.04 上编译，会先后碰到 configure 硬编码路径、C 语言 bool 类型冲突等多个报错，本教程逐一给出原因分析与解决方案。

二、环境准备

1. 硬件要求

官方要求最低 8 GB 内存。实测 make -sj3 编译时峰值占用约 4 GB，8 GB 内存的虚拟机足够；若只有 4 GB，请把编译并发降到 -sj2 并适当加大 swap。磁盘方面，源码约 500 MB、编译中间产物约 2 GB、安装产物约 200 MB、四个数据实例初始化后约 1 GB，共预留 5 GB 以上，生产环境建议 20 GB 以上。

2. 安装系统依赖

以下一条命令安装全部编译依赖（在具有 sudo 权限的用户下执行）：

sudo apt update
sudo apt install -y git gcc g++ make cmake bison flex \
    libreadline-dev zlib1g-dev libssl-dev libxml2-dev \
    libossp-uuid-dev libzstd-dev liblz4-dev libicu-dev \
    libcurl4-openssl-dev libssh2-1-dev sshpass \
    openssh-server language-pack-zh-hans

上面前半部分与官方 README 一致，但有几个包是官方清单没写、实际必需的，见表 2-1。如果还需要在虚拟机里截图做验收记录，可以额外安装 scrot。

3. 创建 opentenbase 用户

OpenTenBase 不允许用 root 运行，需要专用的运行用户。本教程约定：家目录与所有数据都放在 /data/opentenbase：

sudo mkdir -p /data
sudo useradd -d /data/opentenbase -s /bin/bash -m opentenbase
sudo passwd opentenbase          # 设置密码，本教程以 opentenbase 为例
sudo usermod -aG sudo opentenbase
sudo chown -R opentenbase:opentenbase /data/opentenbase

4. 配置 SSH 免密登录

pgxc_ctl 部署工具把每个节点都当作远程主机，即使全部节点都在本机 127.0.0.1，它也会通过 SSH 下发命令。因此 opentenbase 用户必须能免密 SSH 到自己，否则 deploy all 会反复要求输入密码甚至卡死：

su - opentenbase
ssh-keygen -t rsa -N "" -f ~/.ssh/id_rsa
cat ~/.ssh/id_rsa.pub >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
ssh 127.0.0.1 date               # 首次连接输入 yes 记录主机指纹
exit

三、获取源码

1. 方式一：git clone（首选）

su - opentenbase
cd /data/opentenbase
git clone https://github.com/OpenTenBase/OpenTenBase.git

2. 方式二：网络不顺时的替代方案

GitHub 直连不稳定时，git clone 常见两类报错：GnuTLS recv error (-110) 和 Connection refused。以下两个方案均实测可用，优先用方案 A：

# 方案 A：codeload 直接下载源码包（约 36 MB，不走 git 协议）
curl -L -o OpenTenBase-master.tar.gz \
    https://codeload.github.com/OpenTenBase/OpenTenBase/tar.gz/refs/heads/master
tar zxf OpenTenBase-master.tar.gz

# 方案 B：gitcode 平台镜像仓库
git clone https://gitcode.com/OpenTenBase/OpenTenBase.git

两种方式拿到的代码完全一致，后续步骤不区分。后文统一以源码目录 /data/opentenbase/OpenTenBase 为准。

四、编译前的两处源码修改（核心）

这一章是整个安装过程中唯一需要动脑子的地方，也是本教程与官方文档的主要差异。两处修改都源于同一个背景：腾讯内部的编译环境（BINARYLIBS 机制）与我们本地的 Ubuntu 22.04 不同，但开源出的配置脚本没有完全适配。

1. 问题一：configure 硬编码了 libzstd / liblz4 的绝对路径

现象：即使已经安装了 libzstd-dev，configure 仍然报错：

checking for zstd ... configure: error: zstd library not found

原因：用 grep 检查 configure 脚本可以发现，它没有使用系统动态库，而是硬编码了腾讯内部 BINARYLIBS 环境的静态库绝对路径（共 4 处，行号在 12802、12837、12852、12887 附近）：

grep -n "libzstd.a\|liblz4.a" configure
# 12802:  LIBS="/usr/local/lib/libzstd.a $LIBS"   <- Ubuntu 上不存在这个文件
# 12837:  LIBS="/usr/local/lib/liblz4.a $LIBS"    <- 同样不存在

解决：把硬编码路径改成链接器参数，让它去链接 apt 安装的系统库（需要 libzstd-dev 和 liblz4-dev）：

cd /data/opentenbase/OpenTenBase
sed -i "s|/usr/local/lib/libzstd.a|-lzstd|g; s|/usr/local/lib/liblz4.a|-llz4|g" configure
# 验证：不再有 .a 绝对路径
grep -n "lzstd\|llz4" configure | head

2. 问题二：char bool 与 OpenSSL 3.0 的 stdbool.h 冲突

现象：configure 顺利通过后，make 在编译后端源文件时大量报错：

In file included from src/backend/access/common/heaptuple.c:26:
src/include/access/htup_details.h:706:15:
error: conflicting types for 'getmissingattr';
have 'Datum(const TupleDescData *, int, bool *)'
{aka 'long unsigned int(const struct TupleDescData *, int, _Bool *)'}
note: previous declaration of 'getmissingattr' was here (tuptable.h, bool * -> char *)

原因：内核头文件 src/include/c.h 在 C 语言下用 typedef char bool; 自定义了 bool 类型（PostgreSQL 10 时代的写法）。而 Ubuntu 22.04 的 OpenSSL 是 3.0 版本，开启 –with-openssl 编译时，它的头文件会间接把标准头文件 <stdbool.h> 拉进同一个编译单元，其中 _Bool 是编译器内建类型，与 char 定义冲突，同一函数就出现了两个不同的原型。

解决：在 c.h 的 bool 定义之前提前引入标准 <stdbool.h>，让整个工程统一使用标准 _Bool。打开 src/include/c.h，找到大约 220 行的以下代码块：

#ifndef __cplusplus
#ifndef bool
typedef char bool;
#endif

在 #ifndef __cplusplus 和 #ifndef bool 之间插入一行 #include <stdbool.h>。为避免手改出错，可以直接用以下命令自动修改（以实际代码为准，改完后务必 grep 确认）：

cd /data/opentenbase/OpenTenBase
python3 - <<'EOF'
import io
p = "src/include/c.h"
s = io.open(p, encoding="utf-8").read()
old = "#ifndef bool\ntypedef char bool;"
new = "#include <stdbool.h>\n\n#ifndef bool\ntypedef char bool;"
assert old in s, "pattern not found"
io.open(p, "w", encoding="utf-8").write(s.replace(old, new, 1))
print("c.h patched")
EOF
# 验证
grep -n "stdbool" src/include/c.h

重要：如果中途重新解压了源码包，两处修改都会被覆盖，必须重新执行本章的两个补丁步骤再编译。建议把两步补丁写进自己的一键化构建脚本。

五、编译与安装

1. configure 参数说明

表 5-1　configure 参数说明

参数 作用
–prefix=…/opentenbase_bin_v5.0 安装目录。目录名必须叫 opentenbase_bin_v5.0，集群工具按此约定寻址
–enable-user-switch 允许以普通用户（非 root）启动实例
–with-libxml 启用 XML 类型与函数
–disable-license 关闭腾讯内部 license 校验，社区版必选
–with-openssl 启用加密连接（会触发 4.2 节的补丁需求）
–with-ossp-uuid 启用 UUID 生成函数
CFLAGS=”-g” 保留调试符号，便于出错时定位

2. 一次性干净构建

重要经验：务必从全新解压的源码一次性完成 configure 和 make。多次反复 configure 会把不同时刻生成的二进制混在一起，埋下 5.4 节的版本不一致问题（笔者实测两个二进制的编译时间戳相差了 12 分钟，导致 initdb 拒绝启动 postgres）。如果之前编译失败过，先删掉源码目录和安装目录，重新解压、重打第四章两个补丁，再执行：

su - opentenbase
export SOURCECODE_PATH=/data/opentenbase/OpenTenBase
export INSTALL_PATH=/data/opentenbase/install
cd $SOURCECODE_PATH
rm -rf $INSTALL_PATH/opentenbase_bin_v5.0
chmod +x configure
./configure --prefix=$INSTALL_PATH/opentenbase_bin_v5.0 \
    --enable-user-switch --with-libxml --disable-license \
    --with-openssl --with-ossp-uuid CFLAGS="-g"
make -sj3        # 8 GB 内存建议 -j3；内存充足可提高到 -j4
make install

3. 编译 contrib 工具（pgxc_ctl 在这里）

主体 make install 不会安装集群管理工具 pgxc_ctl，它在 contrib 目录里需要单独编译（这一步会用到 g++）：

cd $SOURCECODE_PATH
chmod +x contrib/pgxc_ctl/make_signature
cd contrib
make -sj3
make install

4. 版本一致性验证（必做）

安装完成后验证 initdb 与 postgres 的版本字符串必须完全一致，尤其是末尾的编译时间戳：

$INSTALL_PATH/opentenbase_bin_v5.0/bin/initdb --version
$INSTALL_PATH/opentenbase_bin_v5.0/bin/postgres --version
# 两行输出必须一样，例如：
# initdb (PostgreSQL) 10.0 @ OpenTenBase_v5.0 OpenTenBase V5.21 2026-09-23 21:46:29
# postgres (PostgreSQL) 10.0 @ OpenTenBase_v5.0 OpenTenBase V5.21 2026-09-23 21:46:29

如果两行的时间戳不同（例如一个 21:46:29、一个 21:34:xx），说明安装目录里混入了不同批次的产物。别纠结单个文件，直接回到「一次性干净构建」从全新解压重来一遍最快。后续 initdb 报 postgres was not the same version as initdb 就是这个病因。

六、配置集群

1. 环境变量：必须写在 .bashrc 最顶部

在 opentenbase 用户的 ~/.bashrc（即 /data/opentenbase/.bashrc）最顶部加入以下四行：

export PG_HOME=/data/opentenbase/install/opentenbase_bin_v5.0
export PATH=$PG_HOME/bin:$PATH
export LD_LIBRARY_PATH=$PG_HOME/lib:${LD_LIBRARY_PATH:-}
export LC_ALL=C

注意是最顶部：Ubuntu 的 ~/.bashrc 开头有一段交互检查，非交互场景直接 return 退出，写在它之后的变量对非交互场景无效：

# Ubuntu ~/.bashrc 开头自带：非交互 shell 直接 return
case $- in
    *i*) ;;
      *) return;;
esac

而 pgxc_ctl 部署时正是通过 ssh 127.0.0.1 initdb ... 这样的非交互方式执行命令。如果把环境变量写在交互检查之后，远程会话看不到 PATH，就会满屏 initdb: command not found、pg_ctl: command not found。这是源码安装（非 RPM 包）特有的坑：官方镜像里 PATH 是预配好的。

2. 集群规划

表 6-1　单机四节点端口规划

节点 角色 主端口 数据目录
gtm 全局事务管理器 20001 /data/opentenbase/data/gtm
cn001 协调节点（对外提供 SQL） 30004 /data/opentenbase/data/cn001

每个节点还有一个转发端口和一个连接池端口（例如 cn001 另占 30005、30006），按下面配置文件中的写法保持递增即可。

3. pgxc_ctl.conf 完整配置

创建配置目录 /data/opentenbase/pgxc_ctl，将以下内容保存为 pgxc_ctl.conf（这是实测可用的完整文件，可直接复制）：

#!/bin/bash
pgxcInstallDir=/data/opentenbase/install/opentenbase_bin_v5.0
pgxcOwner=opentenbase
defaultDatabase=postgres
pgxcUser=$pgxcOwner
tmpDir=/tmp
localTmpDir=$tmpDir
configBackup=n
configBackupHost=pgxc-linker
configBackupDir=$HOME/pgxc
configBackupFile=pgxc_ctl.bak
myip=127.0.0.1
rundir=/data/opentenbase/data
clusterMaxMachine=1
clusterMaxParallelQuery=10
#---- GTM ----------
gtmName=gtm
gtmMasterServer=$myip
gtmMasterPort=20001
gtmMasterDir=$rundir/gtm
gtmExtraConfig=none
gtmMasterSpecificExtraConfig=none
gtmSlave=n
gtmSlaveServer=$myip
gtmSlavePort=20002
gtmSlaveDir=$rundir/gtm_slave
gtmSlaveSpecificExtraConfig=none
gtmProxyDir=$rundir/gtm_pxy
gtmProxy=n
gtmPxyExtraConfig=none
gtmPxySpecificExtraConfig=(none)
gtmProxyNames=(gtm_pxy1)
gtmProxyPorts=(20003)
gtmProxyServers=($myip)
gtmProxyDirs=($gtmProxyDir)
gtmHostType=(primary)
gtmHostIdx=(0)
#---- Coordinators -------
coordNames=(cn001)
coordPorts=(30004)
coordForwardPorts=(30005)
poolerPorts=(30006)
coordPgHbaEntries=(127.0.0.0/8)
coordMasterServers=($myip)
coordMasterDirs=($rundir/cn001)
coordMaxWALSenders=(4)
coordSlave=n
coordSlaveSync=n
coordSlaveServers=($myip)
coordSlavePorts=(30007)
coordSlavePoolerPorts=(30008)
coordSlaveDirs=($rundir/cn001_slave)
coordArchLogDirs=($rundir/coord_archlog)
coordExtraConfig=coordExtraConfig
cat > $coordExtraConfig <<EOF
listen_addresses = '*'
wal_level = hot_standby
max_connections = 100
shared_buffers = 256MB
max_pool_size = 200
log_destination = 'csvlog'
logging_collector = on
log_directory = 'pg_log'
log_truncate_on_rotation = on
log_filename = 'postgresql-%A-%H.log'
log_rotation_age = 4h
log_rotation_size = 0
EOF
coordSpecificExtraConfig=(none)
coordExtraPgHba=none
coordSpecificExtraPgHba=(none)
#---- Datanodes ---------------------
primaryDatanode=dn001
datanodeNames=(dn001 dn002)
datanodePorts=(40004 40007)
datanodeForwardPorts=(40005 40008)
datanodePoolerPorts=(40006 40009)
datanodePgHbaEntries=(127.0.0.0/8)
datanodeMasterServers=($myip $myip)
datanodeMasterDirs=($rundir/dn001 $rundir/dn002)
datanodeMaxWALSenders=(4 4)
datanodeSlave=n
datanodeSlaveServers=($myip $myip)
datanodeSlavePorts=(40010 40011)
datanodeSlavePoolerPorts=(40012 40013)
datanodeSlaveSync=n
datanodeSlaveDirs=($rundir/dn001_slave $rundir/dn002_slave)
datanodeArchLogDirs=($rundir/dn001_archlog $rundir/dn002_archlog)
datanodeExtraConfig=datanodeExtraConfig
cat > $datanodeExtraConfig <<EOF
listen_addresses = '*'
wal_level = hot_standby
max_connections = 100
shared_buffers = 512MB
max_pool_size = 200
log_destination = 'csvlog'
logging_collector = on
log_directory = 'pg_log'
log_truncate_on_rotation = on
log_filename = 'postgresql-%A-%H.log'
log_rotation_age = 4h
log_rotation_size = 0
EOF
datanodeSpecificExtraConfig=(none)
datanodeExtraPgHba=none
datanodeSpecificExtraPgHba=(none)

有两个细节容易踩坑：第一，所有数组型变量的元素个数必须与节点数一一对应，例如两个 DN 就必须写 datanodeMaxWALSenders=(4 4)，只写 (4) 会在启动时报 Number of elements in datanode master definitions are different；第二，coordPgHbaEntries=(127.0.0.0/8) 控制客户端白名单，单机环境保持环回地址段即可。若需要从其它机器连接，把对应网段加进去。

七、部署与启动集群

su - opentenbase
cd /data/opentenbase/pgxc_ctl
pgxc_ctl
> deploy all      # 把二进制分发到各节点（本机即本机），生成 pgxc_ctl_bash
> init all        # 初始化 GTM / CN / DN 四个实例并拉起
> monitor all     # 查看状态

monitor all 全部正常时应输出四行 Running（见下方验收截图一）：

Running: gtm master
Running: coordinator master cn001
Running: datanode master dn001
Running: datanode master dn002

日常启停：重启虚拟机后集群不会自动拉起，登录 opentenbase 用户执行 pgxc_ctl 后输入 start all 即可（不需要再 deploy/init）；关闭前先 stop all。另外，刚才的 deploy all 过程中 pgxc_ctl 会在 /data/opentenbase/install 下打包二进制 tar 包，若磁盘紧张可以删掉生成的临时包。

八、数据库初始化与验收

1. 连接协调节点

psql -h 127.0.0.1 -p 30004 -d postgres -U opentenbase

2. 初始化节点组与分片组（源码安装必做）

这是源码安装与官方镜像的又一关键差异：pgxc_ctl 的 init all 不会创建分片映射，直接 CREATE TABLE 会报错 ERROR: default group not defined (42704)，补上节点组后再建表会报 please initialize group ... sharding map first。在 psql 里执行以下两条 SQL 即可一劳永逸：

CREATE DEFAULT NODE GROUP default_group WITH (dn001, dn002);
CREATE SHARDING GROUP TO GROUP default_group;

第一条把两个 DN 组成默认节点组，第二条初始化全局分片映射。相关语法定义在源码 src/backend/parser/gram.y 中（CREATE [DEFAULT] NODE GROUP ... WITH (...) 与 CREATE SHARDING GROUP TO GROUP ...），如果后续想建显式指定分片的表，语法为 DISTRIBUTE BY SHARD(id) TO GROUP default_group。
