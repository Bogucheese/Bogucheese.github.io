## 项目简介

一个前后端分离的 AI 旅游预订平台，起因只有一句话需求：「做一个旅游预订平台，可以提供旅游行程、推荐旅游地点、预订机票、预订酒店」。最终长成了四大功能全链路可用的 MVP：**AI 行程规划、机票预订、酒店预订、目的地推荐**（外加露营板块），并且 AI 不可用时自动降级规则引擎——行程结果永远可用。

## 功能亮点

- **AI 行程规划（Agent 模式）**：模型自主调用 5 个只读工具（查景点 / 查航班 / 搜酒店 / 查真实天气 / 酒店运营状态确认）后再规划；停业酒店自动规避且不可预订；可一键关闭回退单轮模式
- **机票预订**：航线搜索、实时余票、下单扣座（乐观锁）、取消回补，13,560 班「四枢纽辐射网」航线
- **酒店预订（真实数据）**：省/市/区县三级级联选城市（免记三字码）、日期/星级搜索、房型明细（单价×晚数）；30 城约 700+ 家真实酒店（高德 POI 中文名/前台电话/坐标 + trip.com 房价/早餐/评分），真实信息带徽标
- **露营板块**：30 城 1,692 个真实露营地（高德采集），驾车导航走高德真实路网路径规划，天气预报驱动装备清单，评价发布 + LLM 正/负面分析
- **目的地体系**：全国 30 城全覆盖（58 个景点为马蜂窝爬取的真实图片），省→市→县→镇四级级联筛选（GB/T 2260，41,352 个镇街 4MB 懒加载）
- **在线地图**：Leaflet + 高德中文街道底图——行程逐日路线连线带路程、景区与酒店分布、酒店位置图，WGS-84 坐标上图自动纠偏 GCJ-02
- **订单中心**：类型/状态筛选、下单快照、取消回补库存

## 页面布局

- **首页**：目的地大图 Hero + 全局搜索 + 四大功能入口 + 兴趣标签（海滨度假/美食之旅/亲子出游…）+ 热门目的地卡片
- **AI 向导**：三步 `el-steps`（出行信息 → 偏好 → 确认生成），收集目的地/天数/人数/预算/兴趣/酒店档次
- **结果页**：降级提示条 + 逐日时间轴（时段/图标/价格）+ 预算面板 + 推荐机酒卡片（一键预订）+ 行程地图路线
- **订单中心**：列表筛选 + 详情快照 + 取消确认

## 技术栈

| 层次 | 技术 |

| 后端 | Java 21 · Spring Boot 3.4.7 · JPA + H2 文件库（MODE=MySQL，可平滑切换） |
| AI | Spring AI 1.0.9（OpenAI 兼容协议 → 火山方舟，doubao-seed-2-1-lite） |
| 前端 | Vue 3 · Vite · TypeScript · Element Plus · Pinia · Vue Router · Axios |

| 数据采集 | 双引擎爬虫（requests + Playwright 反检测）+ 高德/trip.com 采集管线 |

## 技术难点

- **LLM 输出的七道防线**：只输出 JSON 指令 + `JSON_OBJECT` 响应格式 + 围栏剥离 + 一次"修复 JSON"重试 + 天数完整性校验 + refId 回查/名称模糊匹配/降级 NOTE + 规则引擎兜底——机酒价格与库存一律以服务端实时数据重算，LLM 编造的数字进不了系统
- **深度思考关不掉**：套餐模型默认开深度思考，4 天行程生成 86s 直接打爆读超时；Spring AI 1.0.9 的请求对象没有 `thinking` 字段，最终实测方舟接受 `reasoning_effort: "none"` 透传，86s → 20~35s，输出反而更丰富
- **并发扣减**：下单扣座/扣房用乐观锁，取消回补库存，配合浏览器端到端实测（余票 9→8→回补）
- **坐标系纠偏**：爬来的 WGS-84 坐标直接上高德底图会偏移几百米，上图前统一纠偏 GCJ-02
- **反爬对抗**：robots 用同一 UA 拉取（防 WAF 误判）、懒加载图片取 file 属性、剥离图床尺寸后缀取原图、Playwright 页面反复跳转时每次换全新 page 重试

## 技术亮点

- **端口接口架构**：`FlightSupplierPort` / `HotelSupplierPort` / `LlmPort` 均为端口接口 + Mock/规则实现，将来接真实供应商或换模型，上层零改动
- **永远可用的降级设计**：无 key、假 key（401）、超时、解析失败——任何一环挂掉都降级规则行程（`source=RULE`），HTTP 恒 200，前端明确提示降级原因
- **增量幂等的初始化器**：目的地 10 城 → 30 城扩容时改为按城市码逐城补种，老库启动自动回填；航线判重键一次性载入内存投影查询，启动 9s
- **真实数据规模**：30 城 · 700+ 酒店 · 1,692 露营地 · 13,560 航班 · 41,352 镇街级联数据

## 开发复盘

整个开发过程的技术复盘写在博客：[从 0 到上线：我用 Spring AI + Vue3 做了一个 AI 旅游预订平台](https://lzhcodeblog.site)（以及大区域目的地体系续篇）。最大的教训有两个：一是 LLM 工程的可靠性不靠 prompt 靠防线——把"模型会犯错"当默认前提做工程兜底；二是数据质量决定产品上限，酒店/营地真实数据的采集管线花的时间远超预期，但也是最有壁垒的部分。
